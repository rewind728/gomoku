# 五子棋 · 双人联机

无禁手五子棋，两台手机打开同一个链接就能下。

- **不需要账号**，不需要装 App
- **不需要服务器**，纯静态页面，托管在公网免费平台上
- **一个用 WiFi、一个用流量也没问题**，校园网/4G/5G 都行
- 支持悔棋、和棋、认输、再来一局（自动交换黑白）、快捷语、每步限时

---

## 怎么玩

1. 用手机打开你部署好的链接
2. 点「创建房间」，选好每步限时，把生成的链接发给朋友（微信直接发就行）
3. 对方点开链接自动进入对局，你执黑先行

对局结束后可以点「再来一局」，双方黑白互换。

### 建议加到主屏幕

- **Android**：Chrome 右上角菜单 →「添加到主屏幕」
- **iPhone**：Safari 分享按钮 →「添加到主屏幕」

加完之后是全屏运行，跟原生 App 基本没区别，也不会因为手滑清了浏览器而被当成普通网页。

## 本地预览（自己先试试）

静态页面不能直接双击打开（浏览器的模块加载和跨域限制会拦），必须用 HTTP 服务。

```bash
cd gomoku
python -m http.server 8123
```

然后浏览器打开 <http://127.0.0.1:8123>。

想在电脑上模拟两个人对打：开两个**无痕窗口**分别打开首页和分享链接即可（普通标签页会共用本地存储，两个窗口会被认成同一个玩家）。

## 部署到公网（一次性，之后永久可用）

推荐 **Cloudflare Pages**：免费、自带 HTTPS、地址固定、国内一般能访问。

### 方法一：网页拖拽（最简单，不用命令行）

1. 打开 <https://dash.cloudflare.com>，用邮箱注册并登录（免费，不用绑卡）
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**
3. 项目名随便填，比如 `gomoku`
4. 把 `gomoku` 文件夹里的内容拖进去上传（注意是文件夹**里面**的东西，不是文件夹本身）
5. 部署完成后会得到一个 `https://gomoku-xxx.pages.dev` 的地址，这就是你和朋友要打开的链接

### 方法二：命令行部署（以后改代码方便）

```bash
cd gomoku
npx wrangler pages deploy . --project-name=gomoku
```

第一次运行会跳浏览器让你授权登录，之后每次一条命令就能更新。

### 其他可选的托管

| 平台 | 地址形态 | 国内访问 | 备注 |
|---|---|---|---|
| Cloudflare Pages | `xxx.pages.dev` | 一般可用 | 推荐，免费不限量 |
| Netlify | `xxx.netlify.app` | 一般 | 拖拽部署同样简单 |
| Vercel | `xxx.vercel.app` | 有时被干扰 | 不建议作为首选 |
| GitHub Pages | `xxx.github.io` | 偏慢 | 需要仓库 |
| 国内对象存储（腾讯云 COS / 阿里云 OSS） | 自带域名 | 最快 | 需要实名认证，静态网站托管功能 |

> ⚠️ 域名如果绑自己的，国内服务器需要备案；用平台自带域名则不用。

## 它是怎么联机的（没有服务器的秘密）

```
iPhone  ─┐
         ├── WSS ──→  broker.emqx.io  ──→  只转发 JSON 消息
Android ─┘
     ↑
     └── 静态页面（Cloudflare Pages）
```

两端浏览器都主动**向外**连接一个公共 MQTT 中转站，订阅同一个房间主题。游戏规则、胜负判定、悔棋流程**全部在浏览器里跑**，中转站只负责转发。

这样做的好处：

- **不存在 NAT 穿透问题**——两边都是主动出站，所以在宿舍 WiFi、校园网、4G 之间可以随便组合
- **不用维护任何后端**，不会因为服务器欠费或休眠而玩不了
- **延迟低**：实测消息往返约 290ms，单向约 150ms，下棋完全无感

### 消息协议

主题格式：`gomoku/v1/<20位房间号>`，载荷是 JSON。

| 类型 | 说明 |
|---|---|
| `hello` | 打招呼，用于建立「对手是谁」的身份 |
| `state` | 整盘快照（棋盘 + 落子顺序 + 版本号 + 计时），用于加入、重连、纠偏 |
| `move` | 落子 |
| `undo-req` / `undo-ack` | 悔棋请求 / 应答 |
| `draw-req` / `draw-ack` | 和棋请求 / 应答 |
| `restart-req` / `restart-ack` | 再来一局请求 / 应答 |
| `resign` | 认输 |
| `timeout` | 超时判负 |
| `chat` | 快捷语 |
| `ping` | 心跳，用于判断对手是否掉线 |
| `full` | 房主拒绝第三个人进入 |

每条消息都带发送者 ID 和递增序号，接收端会丢掉重复和乱序的消息。

### 断线重连

手机锁屏、切后台、切网络、刷新页面，都可能把 WebSocket 掐断。处理方式：

- MQTT 客户端自动重连，重连成功后重新打一次招呼
- 对方收到招呼就推一份整盘快照过来
- 对局中每 15 秒双方各推一次整盘快照，用来**补齐可能丢失的消息**
- 14 秒收不到对方心跳，界面上会标「掉线中」

### 快照怎么判断新旧

每次落子或悔棋，本地版本号 `rev` 都会 +1。收到快照时按 `(局数, rev)` 比较：

| 情况 | 处理 |
|---|---|
| 局数更小 | 丢弃（子局已结束） |
| 同局、rev 更小 | 丢弃（这是过期快照） |
| 同局、rev 更大 | 采纳（我落后了，补上丢的消息） |
| 同局、rev 相同但内容不同 | 以房主的版本为准 |

这一条很关键。没有它的话有两个坑会踩到：

1. 刚点「再来一局」，房主广播的空盘快照慢半拍到达，会把客人刚落下的子冲掉
2. 任何一条落子消息丢了，两端就会永远各自为战，谁也发现不了

现在即使丢包，15 秒内也会自动对齐。

## 已知限制（说清楚，免得踩坑）

1. **公共 MQTT 中转站是共享资源**。理论上有心人可以订阅任意主题；房间号是 20 位随机字符串，猜不出来，但这不是密码学意义上的安全。和朋友玩完全够用。
2. **没有防作弊**。两个都是前端，谁改代码谁就赢。朋友之间不需要防。
3. **依赖 `broker.emqx.io` 可用**。它偶尔会慢或者限流。真出问题了，改 `app.js` 顶部的 `BROKER` 常量换一个就行，协议不用动。
4. **`pages.dev` 在某些校园网可能被限速**。如果打不开，换 Netlify 或国内对象存储，页面本身不用改。

## 改参数

都在 `app.js` 顶部：

```js
const BROKER = 'wss://broker.emqx.io:8084/mqtt';  // 换中转站
const PING_MS = 5000;                             // 心跳间隔
const PEER_TIMEOUT_MS = 14000;                    // 多久没心跳算掉线
const REQUEST_TIMEOUT_MS = 20000;                 // 悔棋/和棋请求超时
const QUICK_PHRASES = [...];                      // 快捷语列表
```

棋盘大小在 `rules.js` 的 `SIZE`（默认 15×15），胜负长度是 `WIN_LEN`（默认 5，改大就是「连更多才赢」）。

## 目录结构

```
gomoku/
├── index.html              页面结构（三个界面 + 弹层）
├── styles.css              移动端样式
├── app.js                  联机、对局、渲染
├── rules.js                纯规则：五连判定（可在 Node 里测）
├── manifest.webmanifest    PWA 配置
├── icons/                  图标（含生成脚本）
├── test/rules.test.mjs     规则单元测试
└── vendor/mqtt.esm.js      MQTT 客户端（本地化，不依赖 CDN）
```

`vendor/` 里的 MQTT 客户端是特意下载到本地的——运行时完全不碰境外 CDN，不会因为 CDN 抽风导致页面白屏。

## 规则说明

- 15×15 棋盘，**黑棋先行**
- **无禁手**：不判三三、四四、长连
- 横、竖、斜任意方向连成 **5 子或以上**即获胜（长连也算赢）
- 棋盘下满且无人连成五子算和棋
